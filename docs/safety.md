# Defensive boundaries and untrusted inputs

The engine analyzes JSON reports and structured events only. It does not execute report commands, malware, persistence or exploits; contact extracted destinations; expand shell expressions; or upload reports. Only explicit catalog acquisition and optional loopback Ollama inference use networking. Mapping and queries never update catalogs.

JSON is bounded to 100 MiB and 64 nesting levels; duplicate object keys, nonfinite numbers, malformed structures and unresolved references are rejected. Batches are limited to 100,000 observations; evaluation manifests to 10,000 cases. These upper bounds are parsing constraints, not guarantees of constant memory or acceptable runtime. Large catalogs, metadata retrieval and large batches can require significant resources; use smaller batches and deterministic mode when needed. A 500-event deterministic stress test is included. CLI paths and rule/config files are trusted operator inputs, not destinations extracted from reports. This is not a multitenant API or a complete sandbox for hostile workloads.

Provenance and runtime/static distinctions are required. Direct/reported data may still be inaccurate; external source authenticity, independence and C2 attribution are not verified by schema validation. Scores are heuristic, not probability. Supported behavior does not establish adversarial intent, and absent telemetry does not establish absence of behavior.

Ollama is opt-in and limited to plain loopback HTTP origins. Proxies and redirects are disabled for model requests. Prompts contain bounded application-generated candidate records; raw report descriptions and command lines are not sent. Record strings are treated as untrusted data. Outputs must use allowed mapping/technique IDs, exact evidence IDs and the appropriate rationale code; unexpected fields, invented claims and mismatched codes are rejected before applying any selection. Application-owned prose templates prevent model-authored factual assertions. No model tool/command execution exists, and output cannot promote status, change evidence or modify scores. Requests have bounded responses and timeouts; failures preserve deterministic mapping.

Markdown escapes source-derived HTML, link syntax and formatting. JSON retains provenance and original source references. Reports use unique IDs and exclusive file creation. Existing report/data files are not deleted. No API keys are required, and no credentials belong in report fixtures, setup scripts or repository files.
